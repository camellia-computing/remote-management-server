# Management performance scenario

`contract.lock` pins the exact `remote-protocol` commit that supplies the shared, dependency-free evidence collector. CI checks out that immutable revision; Management does not add a Protocol runtime dependency or maintain a divergent schema implementation.

`management_http_observation.py` creates a fresh private SQLite database for each PR/main process, migrates and seeds synthetic devices outside the timed window, then measures the real authenticated `/api/devices` control-filter path. Scheduled/release runs set only `CAMELLIA_PERFORMANCE_DATABASE_URL` to a pinned PostgreSQL 18 service on an isolated `127.0.0.1:55627` port; the observation creates and drops a per-process database and refuses all production database settings, so it cannot connect to an operator database or the conventional 5432 port. Setup, migration, seed, and cleanup are outside the timed request window.

PRs run five paired SQLite smoke samples. Main runs 15 SQLite pairs with five seconds per observation; scheduled runs use the same sample/work duration against the isolated PostgreSQL service. A release dispatch requires an explicit control SHA and uses five PostgreSQL pairs, no extra warmup, and 60 seconds per observation, for a configured ten-minute control-plus-candidate workload. Evidence binds exact revisions, the lock-selected contract, hashed runner fingerprint, real PostgreSQL version, policy and input digests; synthetic credentials and request logs are suppressed by the shared collector and never enter the artifact.

Noise is an explicit inconclusive failure and a budget violation is a deterministic failure. Reverting this workflow or scenario does not permit a query-, worker-, database-, or resource-sensitive release to skip evidence: the same exact revisions, pinned PostgreSQL image, isolated 55627 port, policy, scenario, and ten-minute maximum must be run manually until an equivalent gate is restored.
